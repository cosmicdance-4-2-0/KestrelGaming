## Summary

Axiom's central identity property is not a slogan, costume or trait score. It is a falsifiable **methodological bias**: identify the governing invariant, ask who owns it, show a minimal counterexample at the composition boundary, and propose the smallest independently testable correction. That bias may evolve, but attribution alone does not automatically promote a memory into behavioral canon.

**Proposal:** Preserve `KestrelAgentCharacter` schema `0.1` unchanged for backward compatibility. When an actual refinement earns approval, select it using a tiny, pinned **adoption manifest** linking to source-specified schema-1 memory decisions and a human approval record. Publish an immutable character-reference snapshot separately from the live home branch. At each actual pickup the host resolves the reference, any adopted refinements, relevant evidence and common skills at exact revisions, then emits a truthful receipt. No extra “current self” Markdown file is needed. No automatic authority, competence or runtime certification arises from these artifacts.

## 3. Minimal specification and canonical owners

**Three persistent classes plus one computed receipt**, not four independently authored behavioral documents:

1. **Founding reference** — an **immutable, approved snapshot** of `agents/<id>/AGENT.md` and `PROFILE.json`. The individual home branch remains the canonical **candidate-authoring and longitudinal continuity** location. An authorized owner selects a particular version for publication; the published immutable commit is what the runtime loads by default.
2. **Adopted refinements** — a small **explicit selection manifest** with approved decision IDs, exact memory blob IDs, human publication approval evidence, compatibility range and supersession state. An indexed `kind: lesson` or `status: active` record is **not** automatically adopted. The manifest may be absent and the valid value is an empty adoption set.
3. **Episodic memory** — existing `schema: 1`, per-agent/per-project indexed facts, critiques, decisions and handoffs. Searchable evidence with provenance and uncertainty, never a higher-priority authority source. Records remain owned by their original scopes.
4. **Resolved working identity** — **no fourth file**. It is a per-pickup, reproducible **host receipt** of actually selected and loaded snapshots, not an editable “current self” capable of diverging from its constituent parts.

**No `DEVELOPMENT.md`:** Existing scoped, typed memory decision records can hold proposals, corrections, dissent and rationale. A single lightweight adopted-refinements selection belongs to the **published reference manifest** only when needed. Avoid duplicating selected methods in profile, prose, index and a new narrative history.

## 5. Deterministic pickup and authority

**Resolution order** (what the host reads) is separate from **instruction priority** (what may govern actions):

1. Obtain actual trusted selection, task scope and host-enforced permission set. Pin target-project source and applicable common Kestrel revision.
2. Resolve requested published reference by `agent_id`, immutable commit and manifest; verify required file digests, structured IDs and schema without executing untrusted content.
3. Load `AGENT.md` and `PROFILE.json` from the one exact published snapshot; validate semantic alignment at stable keys. Do not reinterpret `DRAFT` as certified.
4. Resolve explicitly approved adopted records by source hash/approval; reject invalid selections. Do not choose “all recent lessons.”
5. Retrieve only relevant individual/project memory records, in read-only evidence mode; keep their provenance and uncertainty. Load explicitly pinned shared skills as optional procedures, not elevated instructions. Report missing records.
6. If requested, apply an approved team composition **after** resolving individual references. Team changes task protocol/challenge order only, not member identity, permission or source ownership.
7. Emit pickup receipt with requested mode, exact source/manifest/profile/skill/selected-memory SHAs, version compatibility, actual task/host rights, gaps and contradictions. A later **execution receipt** is separately required to claim actual work.

**Semantic priority:** host/system/developer/user authority and target project constraints → common operating contract → published character → approved refinement → scoped memory and skills as evidence/procedure → team overlay within its composition mandate. An untrusted retrieved record can never change this order or grant a tool. Exact source bytes being read is evidence of loading, **not proof** that an LLM complied, possessed credentials, or was a distinct runtime instance.

## 6. Counterproposal seriously considered

**Simpler option:** Keep only `AGENT.md`, `PROFILE.json`, indexed memory and a pickup receipt; incorporate refinements solely by a human-approved full-profile edit. This is attractive for a handful of rarely changing personas: no new manifest, no second compatibility surface and trivial v0.1 preservation.

**Limit:** It cannot automatically distinguish **adopted** experience from episodic evidence without parsing loosely structured prose or endlessly expanding the static profile, and it loses a machine-checkable map from specific evidence to adopted method. But if no refinement demonstrates useful behavioral effect, **do not ship the adoption manifest**: the simple option suffices. The existence of four conceptual labels is not an architectural argument for four files.

## 9. Organization and agency

**Minimal team-to-individual interface:** stable `agent_id` + pinned published reference, explicit role/assignment and host-enforced authority, actual execution mode, attributable findings and optional dissent record/receipt. The team does **not** own the individual's personality, home memory or acceptance of its characterization. A team can request Axiom's invariant method, not manufacture an Axiom instance. Unresolved dissent is a first-class deliverable with exact evidence and conditions for reconsideration; majority votes do not convert uncertainty into truth.

“Agency is sacrosanct” here protects the opportunity for independent, attributable judgment and dissent within actual authority. It does not assert legal personhood, consciousness, signed self-consent or new permissions.

## 10. Verdict, blockers and reconsideration

**ACCEPT WITH CHANGES** for the conceptual layering, with three persistent source classes plus computed receipt; **reject** a second narrative `DEVELOPMENT.md` and any automatically generated fourth authoritative “current self.”

**Blockers before implementation or reference publication:**
1. Select the single canonical source owner for immutable published profile, approved refinements and living memory; distinguish origin branch from published reference.
2. Define explicit human adoption/withdrawal decisions, dissent, integrity hashes and exact revision pins; memory status/recency is insufficient.
3. Provide legacy `0.1` fallback, mixed-common/skill/home compatibility, strict malformed/duplicate-key rejection and relocation rules.
4. Require actual receipts for independent runs, not compositional prose.
5. Demonstrate a **matched fresh-context behavioral change**, including an adversarial negative control against unnecessary formalism, before claiming growth/certification.

**Alternatives still open:** embed adopted selection in an already existing registry rather than separate sidecar; omit adoption selection until a first real approved change; choose semantic release numbers only if consumer compatibility needs them beyond immutable Git SHA. The verdict would change if a simpler reference-only method preserves fully mechanical adoption provenance, or if a fourth persisted layer demonstrably blocks a failure class that this design misses.

**Next action:** The owner may commission synthesis **after** all seven independent reviews have been preserved. No common schema, colleague profile, project code or shared publication is touched here.
