### Nonblocking input-shape observation

**Location:** model.py lines 235–248 and 261–265. **Evidence:** directly executed exploratory calls outside the declared `str` parameter domain.

```python
lab = SharedDraftLab()
lab.online(False)
resource = ["D1"]
queued = lab.queue_replay(resource)   # QUEUED
resource[0] = "D2"
assert lab.inspect()["intents"][queued.intent_id]["resource"] == ["D2"]
lab.online(True)
lab.retry([])                        # TypeError: unhashable type: 'list'
```

A frozen dataclass does not detach mutable caller data. The origin actor/session remain protected for the declared interface, but a non-string resource can remain aliased; a non-string retry ID can raise rather than produce a normal result. Reconnect of the list resource still reaches the existing resource-type authorization rejection; no unauthorized restore was demonstrated.

**Disposition:** nonblocking for this in-process, explicitly string-ID fixture pass. Do not generalize its immutable-request guarantee to arbitrary Python objects. Before a future public input surface accepts untyped data, define and validate identifier shapes, including response/precedence and no-mutation behavior, or enforce the declared string precondition at that surface. Do not silently invent an authentication or authorization policy to handle a shape error. No implementation change is made by this review.
