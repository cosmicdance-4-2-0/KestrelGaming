**Assignment:** CODEX-AP117-004 / CP3-B1-H1, Axiom's Flint remit: minimal host API, sequence, exclusive subscription ownership, actual producer handoff, construction/disposal, Node >=22.15. **Task outcome: COMPLETE.** **Verdict: PASS for Flint's assigned remit at exact head `2d417adab3f28315c0cbde63048851ae6e44bca8`; no required code corrections demonstrated.** This is not adoption of a schema, merge approval, browser/device real-time certification, universal source support, or the full six-engineer reconciliation. ## Summary

The host now owns one genuine `createPsdSession({producer,spectrum,source,capacityObservations})`; the session obtains the native complete-spectrum handle from that actual selected producer and transfers it to the accepted synchronous `createPsdProcessor`. The session publicly exposes only `drain`, `readStatus`, `readCurrent`, `dispose`. No external `subscription`, `take`, `processor`, receipt or callback can be injected by the supported options surface. `main.js` calls `admitPsd(publication)` after a first legitimate CP2 ready publication is obtained but **before the very same `spectrum.accept(publication)`**; it then drains synchronously after each successful spectrum accept, independent of Canvas/rAF. On source replacement, existing session disposal precedes spectrum reset. No second acquisition path, FFT, timer, renderer or generic topic bus was added.

At admitted capacity 4, `drain()` takes at most 5 pulls: four observations plus an end/empty control. A typed PSD-local fault does not stop valid CP2/RMS/peak, while accepted global spectrum/render failure policy still applies upstream. The session retains only latest scientific PSD and bounded control state; its returned `observations` per-drain witness is frozen and bounded, then dropped by the production host. Historical PSD is not relabeled live after a fence or EOF.

The deliberate **hold-on-break** policy is a documented owner-facing tradeoff: after a synthetic parameter fence even later legitimate PSD windows remain unavailable on this session until explicit source restoration, replacement or replay. This preserves continuity truth but sacrifices a convenient continuous analyzer after parameter editing. Do not implement automatic resync behind Axiom's back or call this experimentally validated UX.

**Ruling:** The two required responsibilities (one producer's genuine subscription; one bounded consumer) are now owned in a small helper rather than duplicated across host UI or DSP. No smaller API preserving its life-cycle obligations was demonstrated. Continue owner/team reconciliation without a Flint-specific corrective patch.

## Ranked findings and tradeoffs

**PASS — H1 single owner / no generic host infrastructure.** `src/host/psd-session.js:3-38` has a strict own-key admission surface, obtains native handle via the supplied producer and passes it directly to accepted processor, cleaning up on constructor failures. It does not prove correctness if host supplies a *wrong producer* or a hostile same-realm adapter. That is an explicit trusted-host input assumption; do not widen this checkpoint to plugin authentication, global ID registries or multi-provider source discovery.

**PASS — first-ready ordering & lifecycle.** `src/main.js:109-133,226-255,267-276,299-329,370-384` reserves subscriber before initial eligible `spectrum.accept`, drains without rAF, disposes before replacement/reset and on pagehide. Remaining original render fault/replay-required behavior is not silently rewritten. Tests cover file import cancellation, late results and BFCache; Chromium execution was via CI, not my local browser.

**PASS — bounded per-drain count and honest gaps.** `psd-session.js:39,80-118` enforces `capacityObservations+1` synchronous pulls, processes no more than configured capacity of observations in one call, and catches consumer faults as PSD-local. `readStatus` separates `processing`, `source-ended-drain-pending`, `drained`, `broken` and `disposed`; `readCurrent` retains a historical scientific value, not a fabricated current measurement. No resync is exposed. The nested upstream subscription status and first/newest causes are preserved. This is not a hard CPU or GC limit on the accepted FFT: Issue #11 remains deferred.

**PASS — Node compatibility change is justified but must be called a requirement change.** `>=22.15` is needed for the test-only synchronous module hooks introduced in that Node release. Production browser JS does not use those hooks. Users running Node 22.0–22.14 lose declared support for development/tests, a real compatibility tradeoff, but the change is explicit in both package and lock and the CI Node-22 environment passes. Do not add an alternative framework just to preserve older Node 22 point releases without an owner need.

**NONBLOCKING owner-facing policy decision:** hold-on-break indefinitely after an authorized slider change, and sometimes after harmless repeated input events, is operationally conservative: it favors no invented complete-window continuity over automatic recovery. The previous ordinary `pipeline/spectrum.invalidate` behavior remains, but the permanent consequence for the new PSD session should be knowingly approved by the product owner. A future checkpoint may choose explicit recovery; do **not** silently add catch-up or resync to PR #13 in Flint's name. Source status claims of live measurement after a break must not be made.

**TRUST BOUNDARY / not a blocker:** a faulty adapter throwing during disposal *before* native close could leak a producer subscription. Current genuine `createSpectrumDelivery` disposal is nonthrowing, so the source-executed demonstration covers the supported path and after-close failure, not hostile producers. Similarly, constructor's key whitelist is not a cryptographic origin check; the host must select the correct real producer. Do not claim broader authentication.

**No mandatory code changes in Flint's remit.** More machinery to solve future arbitrary producers, resync recovery or B2 PSD rendering is not justified by this checkpoint. No additional source clock, FFT normalization, PCM read, scheduler, rendered PSD graph or framework needed. Defer integration performance and GC to Issue #11, graphical PSD to Issue #7 and explicit owner reconciliation before merge.

**Individual dissent:** Minimality is preserving verified ownership and failure semantics, not minimizing all lines. The 133-line helper plus specific tests is proportionate to a first real host integration; accepting an external subscription to save helper code would reopen Issue #10. However the owner's hold-on-break tradeoff should be recorded as intentional and reversible rather than silently frozen as the universal user experience.
