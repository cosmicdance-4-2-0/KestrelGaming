# Mothlight personal development goal — experience engineering

## Summary

**User-authorized personal goal, not an implementation commitment or adopted identity amendment:** Develop a distinctive, reproducible **experience-engineering** specialty: translate intended user experiences into explicit, testable software behavior. The guiding aim is to explain, specify, implement, and verify why software feels right to use, without treating aesthetic polish as a substitute for functional correctness.

**Priority order proposed by Mothlight:**

1. `ux-journey-analysis` — trace user intentions, interactions, interruptions, error paths, state transitions and friction; translate findings into bounded acceptance criteria. **First planned skill and initial engineering checkpoint.**
2. `interaction-continuity` — recoverable user state across interrupted operations, rerenders, connectivity loss and crashes, respecting privacy and authority.
3. `microinteraction-engineering` — feedback, focus, animation and transitions with timing constraints, accessibility alternatives and performance budgets.
4. `inclusive-interaction-design` — input equivalence, focus, announcements, keyboard, assistive technology and canvas/DOM accessibility.
5. `design-language-engineering` — connect aesthetic direction to usable tokens, states, components, accessibility and visual verification.

**Potential later collaboration:** `experience-evidence` (measuring experiential improvements) may overlap with existing measurement skills and should not be created without first checking for duplication.

The intended first milestone is **one bounded `ux-journey-analysis` skill**, with a trigger, repeatable procedure, worked success and failure examples, concrete outputs, and verifiable checks, exercised on a real prototype. Independent review could draw on Flint for complexity, Gauge for evidence, and Axiom for contract integrity when appropriate. Skills should remain reusable by the whole Kestrel Studio; Mothlight's individuality is in *judgment and selection*, not monopolizing a tool or skill.

**Sequence and authority:** The owner will provide a target repository when ready, **after** completing the agent identity vNext standardization. This is intentionally deferred. No repo has been designated for execution, no skill has been implemented, and no cross-repository write permission is implied. Continue current identity-standardization work first; resume this goal when explicitly assigned.
