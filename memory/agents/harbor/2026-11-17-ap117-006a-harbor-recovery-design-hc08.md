# Harbor HC08 — AP117-006A: after the fence, a bounded way back

## Summary

**Recommendation: CONDITIONAL B0 (manual post-fence new segment), retaining A as the approved prototype and fallback.** A is presently the only implemented, owner-conditionally accepted behavior: genuine parameter edits break PSD; the user can explicitly **Use synthetic source** or Replay/replace file, starting a new epoch with no invented continuity. For the later user-configurable instrument, a constrained same-epoch/new-revision segment can avoid an unnecessary source restart **only after** one successful new-revision `spectrum.accept()` has completed the producer's second fence, with the user making a *subsequent explicit choice*. The earliest truthful rejoin is not necessarily the earliest *possible* completion, and the feature must say so.

**My deliberate reduction of B:** **Do not queue an early user request.** Keep the “Start new PSD segment” operation unavailable until the host has witnessed a successful nonfinal CP2-ready accept at the authorized revision and the producer is still eligible. Before that, display “Waiting for the first accepted block at the new settings; PSD remains unavailable” while the unchanged analysis runs. No pending request needs rescheduling across pause, render failure, re-edit or source replacement. A manual click after eligibility constructs a new session on the **actual selected producer**, records its *current* completion frontier and source cursor, and starts only with future delivered windows. If UX testing demands early-click queuing, that is a separately justified and tested addition, not a default requirement.

My invariant: **every recovered observation belongs to one exact, explicitly commenced segment, with the same source-frame clock but a distinct parameter/sourceRevision identity and an honest subscription frontier. A history may contain overlapping sample intervals and still be discontinuous scientifically.**

## Tradeoffs: A, B, and narrower B0

| Alternative | Verified advantage | Cost / invariant burden |
| --- | --- | --- |
| **A — explicit source restart** | Already implemented; clear new epoch, current trusted lifecycle and tests; no extra state | Resets source sample clock and forfeits in-epoch capture; friction for active synthetic controls. Clearer controls help, but do not solve uninterrupted instrument operation. |
| **B — early requested new segment / pending intent** | Can honor a user request made immediately on edit or while paused *after* future successful accept | Must preserve/cancel an authorization ticket across first revised block, second fence, pause, repeated edit, error, final/EOF and source replacement. More state and test surface. |
| **B0 — explicit manual late attachment (my preferred experiment)** | Can reuse same epoch/revision PCM clock, captures true native handle and exact current frontier, avoids a pending-recovery queue and additional scheduler | May require the user to wait for the first revised block and click later; can still permanently lose some completed FFT windows. Must describe loss and attach support, and reject terminal/faulted recovery. |

**Why not immediate auto-attach?** The source's second fence and possible lost first-batch completions make "continue" ambiguous. Automatic restart could silently change the meaning of a continuous analysis series and hide intervals the user never observed. Future B0 needs a clearly visible segment transition; optionally allow an explicit opt-in per edit later, only after proving the pending lifecycle is worth its complexity.

## Minimal B0 contract candidate (not implementation)

**State ownership:** One trusted host source, producer and CP2/PSD path; one currently owned PSD session; **one bounded historical previous-segment summary**, not a retained list of all old spectra. A single host-local `editTicket` is **record of actual successful source revision change**, not a scheduled user request or global token/credential. It contains at least host-selected source identity (sourceId/epoch/channel/tap/clockDomain/sampleRateHz), new sourceRevision, a unique local change discriminator if multiple revisions may alias, and readiness `awaiting-first-revision-accept | eligible | canceled`. Its contents derive from the actual setter and accepted CP2 packet, not DOM text or arbitrary caller-supplied stamps. A no-op setter preserves the existing ticket and session status; a new genuine edit supersedes the ticket, never reviving a stale one.

**Gate 0 — real edit:** Current PSD immediately becomes historical; old session records sticky first/latest cause. Do not dispose its original bound subscription *merely* to forget the reason. Mark the new ticket awaiting its first ready `spectrum.accept()`. No rejoin button yet. Unknown/unwitnessed source revision, changed selected source/epoch/channel, imported file, pagehide/disposal or render fault cancels eligibility. Do not silently create/reuse an edit ticket from a convenient source getter value.

**Gate 1 — **after** successful revised PCM accept:** Only inside the host's existing sequential `advance`: the accepted CP2-ready packet matches all seven authorized source fields and revision, `spectrum.accept(publication)` returns successfully, and `publication.final !== true`; the producer is not terminal/faulted/disposed. Only **after this returned accept** may the ticket become `eligible`. Zero complete windows is allowed. A first new-revision `final` packet makes the candidate terminal/ineligible; do not rejoin with no possible future data. Never mark eligible from `pipeline.advance()` alone, from an unsuccessful FFT accept, or from a render tick.

**Gate 2 — explicit user action:** Make “Start new PSD segment (prior coverage incomplete)” available only when eligible. If the source is paused, the control can attach but must say **awaiting future windows**, not processing or silently resume transport. At the event boundary, recheck selected source identity, revision, ticket/current source epoch, producer openness, and the intended post-fence generation. Dispose the old broken session **before** allocating one new bounded native subscription, preserving the prior summary. If creating the new session fails after disposal (e.g. admission budget), preserve historical data and show **new segment admission failed; zero new PSD observations**; do not roll back the original scientific fence or retry on future PCM without another explicit action. The new session's bound handle supplies its actual `generation`, `continuityRevision` and `attachFrontier=completionOrdinal`; don't match only numeric stamps to an unrelated producer. If this differs from the authorized live producer boundary, reject/close, not silently retarget.

**Gate 3 — first real measurement:** The new association starts with **no ready PSD**, even if the producer's `readCurrent` returns a ready latest FFT or old segment retains a ready historical PSD. Its first truly delivered `inputSpectrum.completionOrdinal` must equal `attachFrontier+1`, unless a new break intervenes. Preserve the first actual `sampleSpan`, current sourceRevision, sampleRate/method and the attach cursor (`endFrameExclusive` of the last success at attachment). It is valid for `firstSpan.startFrame < attachCursor`; record **overlap of sample support** instead of rejecting a legitimate window or calling the preattachment samples freshly acquired. Distinguish (1) unavoidable revision-comparability break, (2) any **count** of completed windows before subscription in that producer generation, (3) support overlap at first delivery, and (4) latest-render coalescing. Unless actual producer evidence enumerates exact omitted spans, label their exact intervals **unknown**, never reconstruct them from a frame animation or current spectrum snapshot.

**Failure/stop matrix:** Invalid or post-final PCM, producer exception, `source-parameters-changed` again, unexpected source revision, subscriber overrun, consumer fault, rendering fault, pause/replay, file import/cancel, channel switch, source replacement, pagehide/BFCache each must cause an explicit state transition; none may create a new segment by themselves. A pause does **not** invalidate an eligible ticket, advance sample time, or acquire new PSD; a *real second edit* revokes it. Render retry alone does not clear a PSD break; terminal/EOF clears eligibility and retains only historical last span. At source end, drain already queued real windows until `take().ended` before reporting `drained`. If an old session failed before any PSD was admitted, say “admission failed” rather than “lost established coverage”; do not fabricate an old segment.

**Capacity/work budget:** Retain `CONFIG.psd.capacityObservations=4` and the producer's native admission limits; no new FFT, PCM acquisition, timer, worker, unbounded queue or Canvas. A batch larger than available capacity breaks that consumer with `subscriber-delivery-overrun` as already implemented; do not split a batch, pad a spectrum, backfill after attach, or claim a complete continuous series. User-visible segment summaries must have an explicit retention bound.

## Minimum falsifying acceptance cases for a separately authorized future PR

1. **Old/new comparison:** Current A still restarts new epoch; B0 old source epoch retained, new sourceRevision and true sample clock preserved; no “continuous across edit” label.
2. **Double fence/zero-window:** The first new-revision `accept` triggers fence even if no completed FFT; no button before it. After it, new subscription starts at actual frontier and first ordinal/half-open sample support are correct, including pre-attachment support in one window.
3. **Negative edit authority:** real edit vs no-op, two quick edits before accept, unexpected/wrong source revision/epoch/channel and wrong producer handle. Stale ticket cannot attach even when numeric delivery generations happen to match.
4. **Interrupted operation:** pause before and after first revised accept, click while paused, producer failure during accept, render failure, retry, file replacement/import pending/canceled, source/channel reset, pagehide/restore. No background attach or old session resurrection.
5. **Terminal:** first revised `final` with zero or multiple forfeited windows; no attach at an already-ended producer, no invented last window; queued finals from an already-valid new session drain before terminal status.
6. **Pressure/exception:** capacities 2 vs 4, a large atomic burst, processor-invalid / throw, failed new-session admission, idempotent disposal; first/latest provenance persists and healthy RMS/peak continue where authorized.
7. **Instrumentation/UX:** Explicit segment provenance, prior historical span, missing-window *count where known* versus support overlap, unavailable state and recover control via keyboard/screen reader; never map Canvas painting to data delivery.
8. **No scope creep:** One CP2 `readBlock`, one FFT `accept`, same host scheduler, no new rendering surface; numerical results unchanged. Issue #11's CPU/GC envelope is separate and still requires empirical measurement.

**All eight are proposed tests — NOT EXECUTED against a B0 implementation.** The seven V8 checks above only exercise existing producer/consumer primitives.

## Dissent and open decisions

- Gauge advocates conditional B with a bounded pending user intent after genuine edit. I agree on **second-fence**, source authority, ordinal/support provenance and fail-closed ownership, but **disagree that an early queued intent is necessary for a first recovery experiment**. Manual attachment available after producer eligibility is simpler and avoids a pending command crossing pause/EOF/fault. This is a candidate UX tradeoff requiring Mothlight's real-user judgment, not a claim that Gauge's option is invalid.
- If user research demonstrates that a delayed second click is unacceptable, revisit a **single bounded early intent** with explicit expiration/cancellation; don't infer that requirement in advance.
- If no B0 pilot demonstrates improved user comprehension without harmful missed-window ambiguity, **choose A** rather than ship more complexity under the name of recovery. The current prototype must retain A until owner design/implementation approval.
- The precise amount of a window's pre-attachment support is available from its real `sampleSpan` and stored attach cursor; precise **unobserved-window spans** may not be. Do not conflate these different claims.
- Do not fold AP117-006A into Issue #11 measured GC/work admission, Issue #7 PSD presentation or Issue #10 native-origin scope, though their independently owned acceptance gates must remain satisfied.

**Disposition:** Design proposal complete; seven bounded source-executed existing-code counterexamples passed; **no B0 code, UI, tests, handoff or user experiment implemented**. No authority asserted for merging or changing the owner conditionally accepted AP117-004 behavior.
